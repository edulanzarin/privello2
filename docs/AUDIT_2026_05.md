## Pontos fortes

### Arquitetura

- **Separação rígida** entre `domain/`, `server/`, `lib/`,
  `components/`. Nenhum primitivo conhece termos de domínio (lint
  estático em `scripts/lint-primitives.ts` valida).
- **Server-only** logic em `src/server/`. Componentes `client`
  consumem APIs via `fetch`.
- **Validação dupla**: schemas Zod em `domain/schemas.ts` + helpers
  `validar*` em `domain/validation/*` reusados em UI e server.
- **Guards centralizados** em `src/server/auth/guards.ts`
  (`requireSession`, `requireCliente`, `requireClienteFan`,
  `requireAcompanhante`, `requireAcompanhanteWithPlano`,
  `requireAdmin`, `requireFile`).

### Segurança

- **Argon2id** com parâmetros calibrados (memoryCost 19456 KiB,
  timeCost 2). Mais memória > mais iterações pra defesa contra GPU.
- **Cookies HMAC SHA-256** (Web Crypto API, Edge-safe). Nome do
  cookie vira `__Host-sessionId` em prod (impede subdomain
  takeover).
- **CSRF same-origin** via `Origin`/`Referer` em todos os route
  handlers via `enforceCsrf`.
- **Open redirect** protegido em `domain/redirect/sanitizarNext`
  — só aceita paths internos (sem `//`, sem `\\`, sem
  `javascript:`).
- **Rate limit por email** no login (banco — 5 falhas / 15 min).
- **Rate limit por IP** em `/api/check-availability` (memória,
  30/min).
- **Path traversal** bloqueado no `/api/storage/[...key]`
  (startsWith STORAGE_DIR; rota só dev).
- **Webhook MP** valida `type === "payment"` antes de processar.
- **Token timing-safe** em `/api/cleanup` (`timingSafeEqual`).
- **Foto privada admin** servida via endpoint dedicado com
  `Cache-Control: no-store` (nunca CDN).

### Banco

- **20 migrations** versionadas com SQL puro (sem `db push`).
- **Triggers SQL** para `likes_count`, `comments_count`,
  `reviews_count` — consistência sem código de aplicação.
- **Índices parciais** otimizados pra busca (`WHERE
  perfil_visivel = true AND plano_vigente IS NOT NULL`).
- **Cascades** corretas em `onDelete: Cascade` para limpeza
  automática de mídias/comentários/likes ao deletar `User`.
- **`ARCHIVED`** preserva histórico de stories (não DELETED).

### UX e design

- **Poppins** carregado com 5 pesos.
- **Glass surfaces** reais (`backdrop-filter: blur` + saturate).
- **Halo warm + textura de papel** no `PageSurface`.
- **Mídia warm consistente**: `accent` (#ec7b5b) e
  `accent-deep` (#c5523a) usados em todos os primitivos.
- **Skeleton + LoadingSpinner** com shimmer/pulse warm.
- **Paginator** com 2 variantes (button glass + link).
- **HeroCollage** com fotos aleatórias da galeria (com blur — não
  destaca conteúdo sensível).
- **CityChips** carrossel de cidades com peek-in.
- **VerifiedBadge** + selo na foto do `ProfileFeedCard`.

## Issues encontradas (priorizadas)

### 🔴 CRÍTICAS

#### C1. EXIF não removido em foto de perfil/capa
**Severidade**: privacy leak.
**Local**: `src/server/storage/profileMedia.ts`,
`replaceCoverPhoto.ts`.

Foto de perfil/capa não passa por `sharp(buffer).rotate()`. EXIF
fica intacto — incluindo **GPS**, modelo da câmera, data/hora.
Atacante pode fazer scrap das fotos públicas e geolocalizar
Acompanhantes.

**Mídias da galeria** já passam pelo watermark (`sharp(...).rotate()`
strippa metadados). Falta replicar pra foto de perfil/capa.

**Fix sugerido**: pipeline `sharp(buffer).rotate().jpeg({...})`
antes do `putStaged` — strippa EXIF mantendo orientação correta.

---

#### C2. Rate limit ausente em endpoints de criação
**Severidade**: spam/DoS.
**Locais**:
- `POST /api/reports`
- `POST /api/medias/[id]/comments`
- `POST /api/medias/[id]/likes`
- `POST /api/acompanhantes/[slug]/reviews`
- `POST /api/acompanhantes/[slug]/questions`
- `POST /api/questions/[id]/answer`
- `POST /api/verificacao`

Apenas `/api/check-availability` tem rate limit. Cliente Fan
malicioso pode:
- Spammar 1000 reviews/min em 1 perfil.
- Spammar denúncias.
- Inflar `comments_count` via spam.

**Fix sugerido**: aplicar `checkRateLimit("comments", userId,
{ max: 10, windowMs: 60_000 })` em todos os POST de criação.
Buckets diferentes por tipo de ação.

---

#### C3. Tabela de denúncias sem unique por reporter+target
**Severidade**: spam doméstico.
**Local**: `prisma/schema.prisma` model `Report`.

Mesmo usuário pode denunciar o mesmo alvo N vezes. Cria ruído na
fila do admin e permite "vote stuffing".

**Fix sugerido**: `@@unique([reporterUserId, targetType,
targetId])` + tratar 409 no service (`criarReport` retorna
`JA_DENUNCIADO`).

---

### 🟡 ALTAS

#### A1. Nudity / NSFW não detectado na collage do hero
**Local**: `src/app/(shell)/_home/HomeView.tsx` HeroCollage.

Collage random pega fotos da galeria sem filtro de nudity. O blur
14px ajuda, mas em mobile (foto pequena) pode ainda revelar
conteúdo sensível.

**Fix sugerido**: rodar uma flag `apropriadaParaCollage:
boolean` na `Media` (default false; Acompanhante marca quais
permitir). Filtrar query por essa flag.

---

#### A2. Nenhum CSP / security headers
**Local**: `next.config.ts`.

Sem `Content-Security-Policy`, `X-Frame-Options`,
`Referrer-Policy`. Site vulnerável a clickjacking + XSS quando
houver injection (mesmo que improvável hoje pelo zero
`dangerouslySetInnerHTML` exceto JSON-LD).

**Fix sugerido**: adicionar `headers()` em `next.config.ts`:

```ts
headers: async () => [{
    source: "/(.*)",
    headers: [
        { key: "X-Frame-Options", value: "DENY" },
        { key: "X-Content-Type-Options", value: "nosniff" },
        { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
        { key: "Permissions-Policy", value: "camera=(), microphone=(self), geolocation=()" },
        { key: "Content-Security-Policy", value: "default-src 'self'; img-src 'self' data: https:; media-src 'self' https:; ..." },
    ],
}],
```

---

#### A3. Endpoint `/api/cleanup` não tem CSRF
**Local**: `src/app/api/cleanup/route.ts`.

Endpoint protegido só por token bearer, sem `enforceCsrf`. Como o
caller é cron (sem cookie de sessão), CSRF não se aplica — mas
se algum dia for chamado de browser, fica vulnerável.

**Status**: aceitável (cron-only).

---

#### A4. Reset de senha sem expiração de email transacional
**Local**: `src/server/auth/passwordReset.ts`.

Tem TODO documentado: "enviar token por email. Por enquanto,
retorna o token na resposta (apenas em dev)". Em prod precisa
plumbar SMTP / SendGrid / Resend antes de abrir.

---

#### A5. Sessions não invalidadas em mudança de email
**Local**: `src/app/api/conta/perfil/route.ts`.

Senha muda → invalida outras sessões (transação atômica). Email
muda → sessions ficam ativas. Atacante que tomou a conta
mantém acesso mesmo se vítima mudar email pra recuperar.

**Fix sugerido**: revogar sessões antigas ao mudar email crítico,
exigir reauth + logar evento de auditoria.

---

#### A6. Verificações expiram não implementado
**Local**: `src/server/verification/index.ts`.

Verificação aprovada **dura pra sempre**. Não há reverificação
periódica (foto pode envelhecer, perfil pode ser tomado por
terceiros).

**Fix sugerido**: campo `verificadaAte: DateTime` (90/180 dias).
Cleanup noturno seta `verificada = false` quando expira; UI
pede reenvio.

### 🟢 MÉDIAS

#### M1. `@deprecated PerfilAcompanhanteResumo` ainda em uso
**Local**: `src/server/acompanhante-profile/index.ts` linha 157.

Type alias mantido por compat. Limpar consumidores antigos
(`grep PerfilAcompanhanteResumo`) e remover.

---

#### M2. ImageOptimization não habilitada
**Local**: 17 ocorrências de `<img>` em vez de `<Image />`.

Performance subótima. Em prod com R2, configurar `next/image`
com `loader` custom apontando pra R2 + remotePatterns no
`next.config.ts`.

---

#### M3. `revalidate=60` agressivo demais na home
**Local**: `src/app/(shell)/page.tsx`.

Home revalida a cada 60s. Boost / cidades / collage random — OK
mas alto pra dados quase estáticos. Considerar 5 min com `tag`
revalidation manual quando criar perfil novo.

---

#### M4. Stories em vídeo não tem poster
**Local**: schema `Media`, `posterStorageKey` opcional. Stories
não geram poster.

UX: quando vídeo demora pra carregar, fundo preto. Adicionar
extração de frame 0 via FFmpeg (já tem `ffmpeg-static`).

---

#### M5. Reels sem thumbnail
**Idêntico ao M4** — `posterStorageKey` opcional, mas pipeline
não gera. Reels carregando ficam pretos.

---

#### M6. Galeria sem ordenação custom
Acompanhante não consegue reordenar mídias. Fica em ordem de
publicação. UX decai com galeria grande.

---

#### M7. Painel admin sem paginação avançada
**Local**: `src/app/admin/_admin/*`.

Listas de até 100 itens. Sem busca, sem filtro por motivo, sem
ordenação. OK pra MVP, ruim com escala.

Apenas `console.error` em 2 arquivos. Sem agregação,
sem context (userId, requestId). Em prod, plumbar
Pino + correlation IDs.

#### B8. Métricas de produto
Sem analytics (Plausible / PostHog / GA). Sem tracking de
conversão (cadastro → seleção plano → boost).

## Sugestões de robustez

### Alta prioridade (1-2 sprints)

1. **Sharp em todas as fotos** (fix C1). 1h de trabalho.
2. **Rate limit em todos POST de criação** (fix C2). 2h.
3. **Unique no Report** (fix C3). 1h migration + service.
4. **Security headers** (fix A2). 30min.
5. **SMTP transacional** (Resend/Postmark) pra reset de senha
   e notificações (fix A4). ~4h.
6. **Reverificação periódica** (fix A6). 2h.

### Média prioridade (3-4 sprints)

7. **NSFW filter** na home (fix A1) — por flag manual ou serviço
   externo (Sightengine / AWS Rekognition).
8. **Image optimization** (fix M2) — `next/image` + R2 loader.
9. **Poster automático** pra Stories+Reels (fix M4/M5).
10. **Sessions revogadas em mudança de email** (fix A5).

### Baixa prioridade (backlog)

11. Galeria reordenável (M6).
12. Admin com filtros (M7).
13. Dark mode + PWA + i18n (B2/B3/B4).
14. Logging + analytics (B7/B8).

## Roadmap visual sugerido

Para o "fatal model level":

### Curto prazo

- **Hero**: vídeo de fundo com loop suave de cidades brasileiras
  (sem foco em pessoas — paisagem urbana). 5-10MB, autoplay
  muted.
- **Search bar**: dropdown com sugestões (top 5 cidades + "Perto
  de mim" via geolocation).
- **Profile cards**: aspect 9:14 (mais alto, estilo Tinder).

### Médio prazo

- **Filtros visuais**: arrastar slider de preço, idade, etnia em
  carousel de chips visuais com fotos representativas.
- **Mapa interativo**: tab "Mapa" na busca com pins agrupados
  (Mapbox / Maplibre).
- **Stories cross-perfil**: collection (estilo Instagram) — ex.:
  "Stories da semana" agregando.

### Longo prazo

- **Vídeo de apresentação** (1 min) além do áudio. Reels integra.
- **Verificação ao vivo**: chamada rápida com admin (~30s) pra
  garantir que pessoa ≠ deepfake.
- **Reservas/agenda**: calendário público + booking direto na
  plataforma com sinal.

## Cobertura de testes

**77/92 passando** (84%).

### Testes falhando (15)

- `foto-perfil-validation` (3) — limite mudou de 10MiB pra 8MiB,
  testes precisam atualizar constante.
- `pos-login-redirect` (3) — redirect pós-login: testes
  desatualizados (provavelmente mudou shape de payload).
- `acompanhante-route-protection` (1) — Property 26 sobre layout.
- `onboarding-atomicity` (1), `onboarding-failure` (2),
  `onboarding-plano-e2e` (3) — stub R2 pode estar
  desatualizado pós-adição do `fetch()` no R2Client.
- `onboarding-validation-reuse` (1), `planos-persistencia` (1).

**Recomendação**: executar `npx vitest run` em CI, atualizar
testes pra refletir limites/shapes atuais. Maioria das falhas
são desalinhamento de fixture com runtime — não regressões.

### Cobertura ausente

- E2E de fluxos completos (cadastro → onboarding → publicar →
  ser denunciado → ser banido). Sem Playwright/Cypress.
- A11y automatizado (sem axe-core no CI).
- Visual regression (sem Chromatic / Percy).

## Conclusão

Codebase **muito acima da média** pra um MVP — separação clara
de camadas, validação dupla, primitivos sem domain leak,
índices SQL pensados, uso correto de transações.

**Bloqueadores pra produção**:
1. EXIF strip (C1).
2. Rate limit em criação (C2).
3. SMTP real (A4).
4. Security headers (A2).

**Total estimado**: ~8-12h de trabalho pra fechar os críticos +
altos. Restante é backlog.
